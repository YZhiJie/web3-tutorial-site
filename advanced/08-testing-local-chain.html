08 · 测试与本地链 ​

需入门约 8 学时 前置：/advanced/07-solidity-patterns验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 说清 Hardhat Network、本地节点与测试网各自适合什么场景。
  • 用 loadFixture 组织部署，让每条测试从同一状态出发且只部署一次。
  • 用 time 推进区块时间，测试截止时间、锁仓与过期逻辑。
  • 写出成功路径、失败路径、边界值与不变量四类测试。
  • 把“随机金额扫描 + 状态不变量”作为轻量 fuzz 手段接入日常门禁。

前置检查 ​

  • 已完成 07 · Solidity 进阶与合约模式。
  • 能读懂 revertedWithCustomError、事件断言与 changeEtherBalances。
  • 本机已执行 pnpm install。

本章示例位于 examples/08-testing-local-chain，合约是三方托管 Escrow，共 10 条测试。

1. 三种“链”的区别 ​

环境生命周期适合不适合
Hardhat Network（进程内）随测试进程启动与销毁单元测试、调试、时间旅行多进程联调
hardhat node / anvil手动启动，持续运行前端联调、脚本演练CI 中的确定性测试
测试网（Sepolia 等）公共网络验证真实部署与浏览器交互快速迭代、精确断言

本仓库没有安装 Foundry，因此进阶示例统一使用 Hardhat Network。概念是相通的：anvil 提供 anvil_setNextBlockTimestamp，Hardhat 提供 time.increaseTo。

fork testing

Hardhat 支持 hardhat_setBalance 与 fork 配置，把主网某個区块的状态复制到本地。它适合验证“和真实协议交互”的代码，但需要 RPC，且区块会移动，因此不适合作为必过门禁。本教程的示例全部离线可跑。

2. 被测试的合约：三方托管 ​

Escrow 有三个角色和一个截止时间：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title Escrow
/// @notice 三方托管：买家出资、买家或仲裁人放款、到期后买家可退款。
contract Escrow {
    // #region escrow-state
    enum State {
        AWAITING,
        FUNDED,
        RELEASED,
        REFUNDED
    }

    address public immutable buyer;
    address public immutable seller;
    address public immutable arbiter;
    uint256 public immutable deadline;

    State public state;
    uint256 public amount;

    event Funded(address indexed buyer, uint256 amount);
    event Released(address indexed seller, uint256 amount);
    event Refunded(address indexed buyer, uint256 amount);

    error NotBuyer(address caller);
    error NotArbiter(address caller);
    error NotBuyerOrArbiter(address caller);
    error InvalidState(State current);
    error ZeroAmount();
    error DeadlineNotReached(uint256 deadline, uint256 now_);
    error TransferFailed();

    modifier onlyBuyer() {
        if (msg.sender != buyer) revert NotBuyer(msg.sender);
        _;
    }

    modifier onlyArbiter() {
        if (msg.sender != arbiter) revert NotArbiter(msg.sender);
        _;
    }

    modifier onlyParticipant() {
        if (msg.sender != buyer && msg.sender != arbiter) revert NotBuyerOrArbiter(msg.sender);
        _;
    }

    modifier inState(State expected) {
        if (state != expected) revert InvalidState(state);
        _;
    }
    // #endregion

    constructor(address buyer_, address seller_, address arbiter_, uint256 deadline_) {
        require(buyer_ != address(0) && seller_ != address(0) && arbiter_ != address(0), 'zero address');
        require(deadline_ > block.timestamp, 'deadline in past');

        buyer = buyer_;
        seller = seller_;
        arbiter = arbiter_;
        deadline = deadline_;
    }

    // #region escrow-fund
    function fund() external payable onlyBuyer inState(State.AWAITING) {
        if (msg.value == 0) revert ZeroAmount();

        amount = msg.value;
        state = State.FUNDED;

        emit Funded(msg.sender, msg.value);
    }
    // #endregion

    // #region escrow-release
    function release() external onlyParticipant inState(State.FUNDED) {
        state = State.RELEASED;

        (bool ok, ) = seller.call{value: amount}('');
        if (!ok) revert TransferFailed();

        emit Released(seller, amount);
    }

    function refund() external onlyArbiter inState(State.FUNDED) {
        state = State.REFUNDED;

        (bool ok, ) = buyer.call{value: amount}('');
        if (!ok) revert TransferFailed();

        emit Refunded(buyer, amount);
    }
    // #endregion

    // #region escrow-claim
    /// @notice 到期后买家自行取回资金，不必依赖仲裁人。
    function claimAfterDeadline() external onlyBuyer inState(State.FUNDED) {
        if (block.timestamp < deadline) revert DeadlineNotReached(deadline, block.timestamp);

        state = State.REFUNDED;

        (bool ok, ) = buyer.call{value: amount}('');
        if (!ok) revert TransferFailed();

        emit Refunded(buyer, amount);
    }
    // #endregion

    /// @notice 供测试与监控使用的不变量：FUNDED 时余额必须等于 amount，其余状态必须为 0。
    function invariantHolds() external view returns (bool) {
        if (state == State.FUNDED) return address(this).balance == amount;
        return address(this).balance == 0;
    }
}

3. fixture：只部署一次，状态彼此隔离 ​

ts
async function deployEscrowFixture() {
  const [buyer, seller, arbiter, outsider] = await ethers.getSigners()
  const deadline = (await time.latest()) + 7 * DAY
  const escrow = await ethers.deployContract('Escrow', [...])
  return { escrow, buyer, seller, arbiter, outsider, deadline }
}

loadFixture 的行为容易误解：

  • 第一次调用：执行 fixture，部署合约，然后拍快照。
  • 之后的调用：回滚到快照，地址不变，状态重置。

所以它既是“部署缓存”，也是“测试隔离”。示例第一条测试专门验证这一点：

ts
const first = await loadFixture(deployEscrowFixture)
await first.escrow.connect(first.buyer).fund({ value: 1n })

const second = await loadFixture(deployEscrowFixture)
expect(await second.escrow.state()).to.equal(0n) // 回到 AWAITING

4. 时间：不要 sleep，要推进区块 ​

ts
await expect(escrow.connect(buyer).claimAfterDeadline())
  .to.be.revertedWithCustomError(escrow, 'DeadlineNotReached')

await time.increaseTo(deadline)
await escrow.connect(buyer).claimAfterDeadline()

要点：

  • 用 increaseTo 设置绝对时间戳，避免“测试跑了多久”影响结果。
  • 合约里比较的是 block.timestamp，不是墙钟时间。
  • 涉及 block.number 的逻辑要用 mine，不要假设“一笔交易只出一个块”。

5. 四类测试分别拦什么 ​

类型例子能拦住的问题
成功路径买家出资、卖家收款主流程被改坏
失败路径非买家出资、过期前取回权限与状态校验缺失
边界值金额 0、重复调用、刚好到期off-by-one、状态机漏洞
不变量余额与 amount 一致资金被卡死或凭空出现

不变量写成合约里的只读函数，测试与监控都能复用：

const amounts = [1n, 2n, 3n, 5n, 8n, 13n, 21n, 34n, 55n, 89n].map((n) => n * 10n ** 15n)
for (const value of amounts) {
  const fresh = await loadFixture(deployEscrowFixture)
  await fresh.escrow.connect(buyer).fund({ value })
  expect(await fresh.escrow.invariantHolds()).to.equal(true)
  await fresh.escrow.connect(buyer).release()
  expect(await fresh.escrow.invariantHolds()).to.equal(true)
}

它不如真正的属性测试强大，但胜在：

  • 失败可复现：金额序列固定，CI 不会随机飘。
  • 成本低：10 个输入在本地不到 100ms。
  • 能覆盖“金额不影响状态守恒”这类核心性质。

如果后续引入 Foundry，可以把同一组性质改写成 invariant_ 函数，测试目标不变。

7. 本地节点与前端联调 ​

启动一个持续运行的本地链：

bash
pnpm --filter @web3-ex/08-testing-local-chain exec hardhat node
1

另开终端部署：

bash
pnpm --filter @web3-ex/08-testing-local-chain exec hardhat run scripts/deploy.ts --network localhost
1

本章示例没有部署脚本；需要时参考 04-counter 的 scripts/deploy.ts。联调时注意：

  • hardhat node 的账户私钥是公开的，只能用于本地。
  • 页面刷新不会改变链上状态，但重启节点会清空全部数据。
  • 前端应把链 ID 固定为 31337，避免误连测试网。

8. 常见坑 ​

  • 把 loadFixture 当 beforeEach 用：它不会重新部署，只回滚状态；需要新地址就显式部署。
  • 在循环里不重置状态：同一合约连续操作会互相影响，fuzz 每一轮都应 loadFixture。
  • 只断言交易成功：成功但状态错误是最难查的 bug，务必断言存储与事件。
  • 用 time.increase 做绝对判断：边界测试应优先 increaseTo。
  • 把 fork 测试放进必过门禁：RPC 抖动会让 CI 不稳定，fork 测试应单独标记。
  • 忽略 gas 与余额断言中的手续费：changeEtherBalances 会处理发送方 gas，手写 getBalance 不会。

9. 练习题 ​

  1. 给 Escrow 增加 extendDeadline(uint256)，只允许仲裁人调用且只能延长，补两条边界测试。
  2. 把 fuzz 金额改成 100 个由固定种子生成的随机值，保证失败可复现。
  3. 写一条测试：卖家在 RELEASED 后再次调用 release，断言错误参数是当前状态。
  4. 设计一个不变量，覆盖“任一时刻合约余额不超过所有托管金额之和”，并说明为什么当前单合约模型下它等价于 invariantHolds。
