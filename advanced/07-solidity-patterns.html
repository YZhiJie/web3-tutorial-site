07 · Solidity 进阶与合约模式 ​

需入门约 6 学时 前置：/guide/06-first-dapp验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 用接口隔离调用方与实现，避免把整个合约当成 ABI。
  • 设计“角色 + 暂停”的权限结构，而不是只有一个 owner。
  • 解释 push 与 pull payment 的差异，并写出不会被单个收款方卡死的提现逻辑。
  • 用 checks-effects-interactions 与重入锁组合防御重入。
  • 理解 delegatecall 代理的存储布局约束，完成一次 V1 → V2 升级。

前置检查 ​

  • 已完成 06 · 第一个 dApp。
  • 能独立编写带事件、自定义错误和修饰器的合约。
  • 能读懂 Hardhat 测试中的 revertedWithCustomError 与事件断言。

本章示例位于 examples/07-solidity-patterns，共 4 个可部署合约与 1 个攻击合约、11 条测试。示例故意保持小，每个模式对应一个独立文件，方便逐段对照。

1. 接口：只暴露调用方需要的东西 ​

调用另一个合约时，不需要 import 它的完整源码，只需要知道函数选择器和参数：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @notice 只暴露攻击者需要的入口；调用方不必依赖完整实现。
// #region interface
interface IAccessVault {
    function deposit() external payable;

    function withdrawGuarded() external;
}
// #endregion

好处有三点：

  • 编译依赖更小，调用方不会被实现合约的内部类型拖累。
  • ABI 边界清晰，升级实现时只要接口不变，调用方无需改动。
  • 审计时可以先看接口，再看实现，减少遗漏。

注意接口里的函数必须与实现的选择器一致。deposit() 与 deposit(uint256) 是两个不同的函数，不能想当然。

2. 权限：owner、角色与暂停 ​

单一 owner 适合教学，不适合生产。示例把权限拆成三层：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title AccessVault
/// @notice 教学合约：权限、暂停、pull payment 与重入锁的组合。
contract AccessVault {
    // #region access-control
    address public owner;
    bool public paused;
    mapping(address => bool) public operators;

    event OperatorUpdated(address indexed operator, bool allowed);
    event PausedState(bool paused);

    error NotOwner(address caller);
    error NotOperator(address caller);
    error Paused();
    error ZeroAddress();

    modifier onlyOwner() {
        if (msg.sender != owner) revert NotOwner(msg.sender);
        _;
    }

    modifier onlyOperator() {
        if (!operators[msg.sender]) revert NotOperator(msg.sender);
        _;
    }

    modifier whenNotPaused() {
        if (paused) revert Paused();
        _;
    }

    constructor() {
        owner = msg.sender;
    }

    function setOperator(address operator, bool allowed) external onlyOwner {
        if (operator == address(0)) revert ZeroAddress();
        operators[operator] = allowed;
        emit OperatorUpdated(operator, allowed);
    }

    function setPaused(bool value) external onlyOwner {
        paused = value;
        emit PausedState(value);
    }
    // #endregion

    // #region pull-payment
    mapping(address => uint256) public pendingWithdrawals;

    event Deposit(address indexed account, uint256 amount);
    event Withdrawal(address indexed account, uint256 amount);

    error NothingToWithdraw(address account);
    error TransferFailed();

    function deposit() external payable whenNotPaused {
        pendingWithdrawals[msg.sender] += msg.value;
        emit Deposit(msg.sender, msg.value);
    }

    /// @notice 运营方代用户入账，用于演示角色权限。
    function credit(address account) external payable onlyOperator whenNotPaused {
        pendingWithdrawals[account] += msg.value;
        emit Deposit(account, msg.value);
    }

    /// @notice 收款方主动提取，合约不主动转账给任何人。
    function withdraw() external {
        uint256 amount = pendingWithdrawals[msg.sender];
        if (amount == 0) revert NothingToWithdraw(msg.sender);

        // 先清零再转账：checks-effects-interactions
        pendingWithdrawals[msg.sender] = 0;

        (bool ok, ) = msg.sender.call{value: amount}('');
        if (!ok) revert TransferFailed();

        emit Withdrawal(msg.sender, amount);
    }
    // #endregion

    // #region reentrancy
    uint256 private constant NOT_ENTERED = 1;
    uint256 private constant ENTERED = 2;
    uint256 private _status = NOT_ENTERED;

    error ReentrantCall();

    modifier nonReentrant() {
        if (_status == ENTERED) revert ReentrantCall();
        _status = ENTERED;
        _;
        _status = NOT_ENTERED;
    }

    function withdrawGuarded() external nonReentrant {
        uint256 amount = pendingWithdrawals[msg.sender];
        if (amount == 0) revert NothingToWithdraw(msg.sender);

        pendingWithdrawals[msg.sender] = 0;

        (bool ok, ) = msg.sender.call{value: amount}('');
        if (!ok) revert TransferFailed();

        emit Withdrawal(msg.sender, amount);
    }
    // #endregion

    receive() external payable {
        pendingWithdrawals[msg.sender] += msg.value;
        emit Deposit(msg.sender, msg.value);
    }
}

三个设计点：

  1. 角色用映射而不是枚举：mapping(address => bool) 可以按需增删运营方，不需要改代码。
  2. 暂停是独立开关：出问题时先暂停入账，再排查，不必紧急升级合约。
  3. 错误带调用者：NotOwner(msg.sender) 让链下日志能直接指出是谁越权。

生产环境还会再加两道约束：

  • owner 指向多签或 timelock，而不是单个 EOA。
  • 关键操作（升级、改费率）发事件并设置延迟，给用户反应时间。

权限不是“写个 onlyOwner 就完事”

如果 owner 可以随时转走合约资金，那么它本质上仍是一个中心化托管。教程里的 AccessVault 没有管理员提现函数，就是为了让“用户自己提款”成为唯一的资金出口。

3. pull payment：让收款方自己来取 ​

push 模式是合约主动给地址转账：

solidity
payable(recipient).transfer(amount); // 收款方失败会拖垮整笔交易

对比：

模式优点风险
push收款方无需额外操作恶意收款方可以 revert，阻塞批量发放
pull单个收款方失败不影响其他人用户需要自己发起提现交易

withdraw 里先清零再转账，是 checks-effects-interactions 的标准顺序：

  1. Checks：余额是否为 0。
  2. Effects：把 pendingWithdrawals 置 0。
  3. Interactions：最后才执行外部调用。

4. 重入：为什么光有 CEI 还不够 ​

上面的 withdraw 已经先清零，所以重入时第二次读取到 0，会以 NothingToWithdraw 失败。但如果未来有人在 effects 之前加了新的外部调用，防护就会失效。重入锁是一层与业务顺序无关的保险：

import './IAccessVault.sol';

/// @notice 模拟重入攻击：在 receive 里再次调用 withdrawGuarded。
// #region attacker
contract ReentrancyAttacker {
    IAccessVault public immutable vault;

    constructor(address payable vault_) {
        vault = IAccessVault(vault_);

    function attack() external payable {
        vault.deposit{value: msg.value}();
        vault.withdrawGuarded();
    }

    receive() external payable {
        // 无条件重入：展示 nonReentrant 修饰器的拦截效果。

}

5. 可升级：delegatecall 与存储布局 ​

代理模式的核心是：用户始终调用代理地址，代理用 delegatecall 执行实现合约的代码，但读写的是代理自己的存储。

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @notice 最小 delegatecall 代理：实现地址存在 EIP-1967 槽，避开逻辑合约的存储布局。
contract SimpleProxy {
    // #region proxy-core
    bytes32 private constant IMPLEMENTATION_SLOT =
        0x360894a13ba1a3210667c828492db98dca3e2076cc3735a920a3ca505d382bbc;

    address public immutable deployer;

    error NotDeployer(address caller);
    error ZeroAddress();

    constructor(address implementation_) {
        if (implementation_ == address(0)) revert ZeroAddress();
        deployer = msg.sender;
        _setImplementation(implementation_);
    }

    function implementation() external view returns (address impl) {
        assembly {
            impl := sload(IMPLEMENTATION_SLOT)
        }
    }

    function upgrade(address newImplementation) external {
        if (msg.sender != deployer) revert NotDeployer(msg.sender);
        if (newImplementation == address(0)) revert ZeroAddress();
        _setImplementation(newImplementation);
    }

    function _setImplementation(address impl) private {
        assembly {
            sstore(IMPLEMENTATION_SLOT, impl)
        }
    }

    /// @notice 纯转账不代理，避免把实现合约的 fallback 当成收款入口。
    receive() external payable {}

    fallback() external payable {
        assembly {
            let impl := sload(IMPLEMENTATION_SLOT)
            calldatacopy(0, 0, calldatasize())
            let result := delegatecall(gas(), impl, 0, calldatasize(), 0, 0)
            returndatacopy(0, 0, returndatasize())
            switch result
            case 0 {
                revert(0, returndatasize())
            }
            default {
                return(0, returndatasize())
            }
        }
    }
    // #endregion
}

三个关键点：

  1. 实现地址不能放在 slot 0。逻辑合约的 value 就在 slot 0，冲突会把计数器写成实现地址。示例使用 EIP-1967 约定槽位。
  2. fallback 负责转发。calldatacopy → delegatecall → returndatacopy，失败时原样 revert，成功时原样 return。
  3. 升级权限必须收窄。示例只允许部署者升级；生产环境应使用多签 + timelock。

V1 只有 value：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @notice 可升级逻辑 V1：只有 value 一个状态变量。
// #region counter-v1
contract CounterV1 {
    uint256 public value;

    event Initialized(uint256 start);

    error AlreadyInitialized();

    function initialize(uint256 start) external {
        if (value != 0) revert AlreadyInitialized();
        value = start;
        emit Initialized(start);
    }

    function increment() external virtual {
        value += 1;
    }

    function version() external pure virtual returns (string memory) {
        return 'v1';
    }
}
// #endregion

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import './CounterV1.sol';

/// @notice 可升级逻辑 V2：新增 step，放在 value 之后的槽位，保持存储布局兼容。
// #region counter-v2
contract CounterV2 is CounterV1 {
    uint256 public step;

    function setStep(uint256 newStep) external {
        step = newStep;
    }

    function increment() external override {
        uint256 delta = step == 0 ? 1 : step;
        value += delta;
    }

    function version() external pure override returns (string memory) {
        return 'v2';
    }
}
// #endregion

升级的三个常见事故

  • 新逻辑把状态变量顺序改了，旧数据被当成新含义。
  • 构造函数不再执行，忘了显式初始化。
  • 实现合约本身可以被直接调用，留下“只有代理才该持有资金”的假象。

11 条测试分为两组：

  • AccessVault：权限、暂停、运营方入账、pull payment、空余额、重入攻击、直接转账。

每条测试都同时断言状态与事件/错误，避免“交易成功但结果不对”。

7. 常见坑 ​

  • 接口与实现选择器不一致：改了参数类型但忘了同步接口，编译能过，调用会 fallback。
  • pause 只挡了入口没挡出口：暂停时仍应允许用户提现，否则资金被锁死。
  • 重入锁只加在一个函数上：所有会做外部调用的入口都要加，或统一走内部函数。
  • 代理的 receive 直接收钱：示例的 receive() 是空的，不代理；如果业务需要收款，要显式转发。
  • 升级后不验证存储：至少写一条“升级后旧状态仍在”的回归测试。
  • 把 delegatecall 用在不可信合约上：被调用方可以改写调用方的任意存储。
