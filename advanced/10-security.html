10 · 合约安全 ​

需入门约 6 学时 前置：/advanced/07-solidity-patterns、/advanced/08-testing-local-chain验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 用攻击者视角复现重入与权限提升，而不是只背漏洞名词。
  • 为每个漏洞写出“攻击测试 + 修复版 + 回归测试”三件套。
  • 识别预言机操纵、精度损失、签名重放与拒绝服务的高危模式。
  • 建立一份能落地的上线前检查清单。

前置检查 ​

  • 已完成 07 · Solidity 进阶与合约模式。
  • 已完成 08 · 测试与本地链。
  • 能读写 call、delegatecall、tx.origin 与修饰器。

本章示例位于 examples/10-security，9 条测试，全部离线可复现。

仅用于教学

本章的“漏洞版”合约故意不安全，禁止部署到任何真实网络。攻击合约同理。

1. 先定义攻击者模型 ​

审计前先回答四个问题：

问题说明
攻击者能控制什么？普通用户、合约调用方、代币、预言机输入、区块时间
攻击者想得到什么？资金、权限、拒绝服务、清算优势
攻击者要付什么成本？Gas、抵押品、被发现后的追溯风险
哪些假设是“可信”的？多签、timelock、去中心化预言机、审计过的库

没有攻击者模型的“安全检查”只是名词清单。

2. 靶场一：重入抽干金库 ​

漏洞版把清零放在外部调用之后：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title EtherVault（漏洞版）
/// @notice 故意把余额清零放在外部调用之后，可被重入抽干。仅用于靶场教学。
contract EtherVault {
    // #region vulnerable-vault
    mapping(address => uint256) public balances;

    event Deposited(address indexed account, uint256 amount);
    event Withdrawn(address indexed account, uint256 amount);

    function deposit() external payable {
        require(msg.value > 0, 'zero amount');
        balances[msg.sender] += msg.value;
        emit Deposited(msg.sender, msg.value);
    }

    function withdraw() external {
        uint256 amount = balances[msg.sender];
        require(amount > 0, 'no balance');

        // 先转账，后清零：攻击者可以在 receive 中再次进入
        (bool ok, ) = msg.sender.call{value: amount}('');
        require(ok, 'transfer failed');

        balances[msg.sender] = 0;
        emit Withdrawn(msg.sender, amount);
    }
    // #endregion
}

攻击合约在收到 ETH 时再次调用 withdraw：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import './EtherVault.sol';

/// @notice 重入攻击合约：收到退款时再次调用 withdraw，直到金库被抽干。
contract VaultAttacker {
    // #region attack-receive
    EtherVault public immutable vault;

    constructor(address payable vault_) {
        vault = EtherVault(vault_);
    }

    function attack() external payable {
        vault.deposit{value: msg.value}();
        vault.withdraw();
    }

    receive() external payable {
        if (address(vault).balance > 0) {
            vault.withdraw();
        }
    }
    // #endregion
}

关键不是“攻击者会写 receive”，而是外部调用会把手控制权交给对方。只要对方是合约，就有机会在状态更新前再次进入。

修复版同时使用 CEI 与重入锁：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title FixedVault
/// @notice 修复版：checks-effects-interactions + 重入锁。
contract FixedVault {
    // #region fixed-vault
    mapping(address => uint256) public balances;

    uint256 private constant NOT_ENTERED = 1;
    uint256 private constant ENTERED = 2;
    uint256 private _status = NOT_ENTERED;

    event Deposited(address indexed account, uint256 amount);
    event Withdrawn(address indexed account, uint256 amount);

    error ReentrantCall();
    error NoBalance();

    modifier nonReentrant() {
        if (_status == ENTERED) revert ReentrantCall();
        _status = ENTERED;
        _;
        _status = NOT_ENTERED;
    }

    function deposit() external payable {
        require(msg.value > 0, 'zero amount');
        balances[msg.sender] += msg.value;
        emit Deposited(msg.sender, msg.value);
    }

    function withdraw() external nonReentrant {
        uint256 amount = balances[msg.sender];
        if (amount == 0) revert NoBalance();

        // 先清零，后转账
        balances[msg.sender] = 0;

        (bool ok, ) = msg.sender.call{value: amount}('');
        require(ok, 'transfer failed');

        emit Withdrawn(msg.sender, amount);
    }
    // #endregion
}

修复后的回归测试断言三件事：

  • 攻击交易 revert。
  • 金库余额仍为 5 ETH。
  • 攻击合约余额为 0（整笔交易回滚，存入的 1 ETH 也退回）。

低级调用会吞掉内层错误

攻击被拦截时，测试看到的是外层 transfer failed，不是内层的 ReentrantCall。排查要结合调用栈，不能只看最外层错误名。

3. 靶场二：tx.origin 权限提升 ​

漏洞版用 tx.origin 判断 owner：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title PhishableWallet（漏洞版）
/// @notice 用 tx.origin 做权限判断，可被中间合约借用户之手改掉 owner。
contract PhishableWallet {
    // #region vulnerable-owner
    address public owner;

    event OwnerChanged(address indexed previousOwner, address indexed newOwner);

    constructor() {
        owner = msg.sender;
    }

    function transferOwnership(address newOwner) external {
        require(tx.origin == owner, 'not owner');
        emit OwnerChanged(owner, newOwner);
        owner = newOwner;
    }

    function withdraw() external {
        require(msg.sender == owner, 'not owner');
        (bool ok, ) = owner.call{value: address(this).balance}('');
        require(ok, 'transfer failed');
    }
    // #endregion

    receive() external payable {}
}

text
tx.origin = 用户（真正的 owner）

require(tx.origin == owner) 通过，owner 被改成攻击合约，随后资金被转走。

修复版只认 msg.sender，并把转移改成两步：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title SafeWallet
/// @notice 修复版：msg.sender 权限 + 两步转移。
contract SafeWallet {
    // #region fixed-owner
    address public owner;
    address public pendingOwner;

    event OwnerChanged(address indexed previousOwner, address indexed newOwner);
    event OwnershipTransferStarted(address indexed currentOwner, address indexed pendingOwner);

    error NotOwner(address caller);
    error NotPendingOwner(address caller);

    modifier onlyOwner() {
        if (msg.sender != owner) revert NotOwner(msg.sender);
        _;
    }

    constructor() {
        owner = msg.sender;
    }

    function transferOwnership(address newOwner) external onlyOwner {
        pendingOwner = newOwner;
        emit OwnershipTransferStarted(owner, newOwner);
    }

    function acceptOwnership() external {
        if (msg.sender != pendingOwner) revert NotPendingOwner(msg.sender);
        emit OwnerChanged(owner, msg.sender);
        owner = msg.sender;
        pendingOwner = address(0);
    }

    function withdraw() external onlyOwner {
        (bool ok, ) = owner.call{value: address(this).balance}('');
        require(ok, 'transfer failed');
    }
    // #endregion

    receive() external payable {}
}

两步转移的价值：

  • 新 owner 必须主动调用 acceptOwnership，输错地址不会立即生效。
  • 攻击合约无法替用户“接受”，因为它不是新 owner。
  • 转移过程有事件，监控可以发现异常。

4. 其他四类高频问题 ​

4.1 预言机操纵 ​

典型错误是直接用现货池子的瞬时价格：

solidity
// 危险：一笔大额 swap 就能把价格推偏
uint256 price = reserve1 * 1e18 / reserve0;
1
2

防线：

  • 使用时间加权平均价格（TWAP），并设置最小观察窗口。
  • 多源聚合，偏离阈值时暂停。
  • 关键清算设置价格上限/下限与断路器。

4.2 精度与舍入 ​

solidity
uint256 shares = assets * totalSupply / totalAssets; // totalAssets 为 0 时除零
uint256 fee = amount * feeBps / 10_000;             // 小额时 fee 可能为 0
1
2

防线：

  • 明确舍入方向：协议永远不要向上舍入给用户。
  • 对 totalAssets == 0、amount < 1e4/feeBps 等边界写测试。
  • 先乘后除，避免中间精度损失。

4.3 签名重放 ​

solidity
// 危险：没有 chainId、合约地址、nonce
bytes32 digest = keccak256(abi.encodePacked(user, amount));
1
2

防线：

  • 使用 EIP-712 domain：chainId + verifyingContract。
  • 每笔签名带递增 nonce，并在链上标记已用。
  • 设置过期时间，避免旧签名永久有效。

4.4 拒绝服务 ​

常见来源：

  • 循环里给所有用户 push 转账，一个人 revert 就全失败。
  • 依赖 address(this).balance 作为会计变量，被强制转入 ETH 打乱。
  • 无上限的数组遍历，Gas 随用户数增长。

防线：pull payment、独立记账变量、分页处理。

5. 上线前检查清单 ​

类别检查项
权限是否只用 msg.sender；owner 是否多签 + timelock
外部调用是否 CEI；是否有重入锁；是否限制 gas/返回值
资金余额与内部记账是否一致；是否有不变量测试
预言机是否可被单笔交易操纵；是否有 staleness 检查
数学舍入方向；除零；极值；先乘后除
签名domain 分离；nonce；过期时间
升级存储布局；初始化；管理员权限
监控关键事件；异常阈值；暂停开关

6. 测试与工具 ​

bash
pnpm --filter @web3-ex/10-security test
1

9 条测试分为两组：

  • 重入：漏洞版抽干、正常路径、修复版拦截、修复版正常路径、空余额。
  • 权限：漏洞版钓鱼、修复版拒绝、两步转移、非 owner 发起。

工具层面的建议：

  • 静态分析（Slither 等）能扫出常见模式，但不能替代攻击测试。
  • 不变量测试覆盖“任何调用序列后资金守恒”。
  • 上线前做一次独立审计；升级前后各跑一次全量门禁。

7. 常见坑 ​

  • 只修一处重入：所有外部调用入口都要覆盖，或统一走内部函数。
  • 用 tx.origin 做权限：这是最容易被钓鱼利用的写法。
  • 把 call 的成功当业务成功：对方可能返回 true 但没做任何事。
  • 忽略 ERC-20 的返回值差异：有的代币不返回 bool，直接 require(token.transfer(...)) 会失败。
  • 修复后不写回归测试：下次重构可能把漏洞带回来。
  • 把“审计过”当成免死金牌：审计报告有时效性，升级会引入新风险。

8. 练习题 ​

  1. 给 EtherVault 增加 withdrawAll()，写出对应的重入攻击与修复测试。
  2. 把 SafeWallet.withdraw 改成 pull payment，说明它如何降低 DoS 风险。
  3. 为一个“按现货价格清算”的借贷合约写攻击测试，展示单笔 swap 造成的坏账。
  4. 设计一个签名重放测试：同一签名在两条链上都能通过时，说明缺少哪个字段。
