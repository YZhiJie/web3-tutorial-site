17 · MEV ​

需进阶约 4 学时 前置：/advanced/12-defi、/advanced/14-l2-bridge验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 解释 MEV 的来源：套利、清算、三明治、抢跑与回滚。
  • 用恒定乘积池推演一次三明治攻击的资金流。
  • 说明滑点保护为什么能阻止单笔交易被夹，以及它的局限。
  • 区分 searcher、builder、proposer、relay 的角色与 PBS 的作用。
  • 列出 dApp 与用户侧的 MEV 防护清单。

前置检查 ​

  • 已完成 12 · DeFi 与 14 · L2 与跨链。
  • 理解恒定乘积 AMM 与滑点。
  • 知道交易在 mempool 中可见，排序由区块生产者决定。

本章示例位于 examples/17-mev，纯 Node ESM，10 条离线测试，不连接真实 mempool。

仅用于防御

示例只做离线资金流模拟，用于理解风险与设计防护。不要把它改造成真实链上的攻击工具。

1. MEV 的五种常见来源 ​

类型机制受害者
套利同一资产在不同池存在价差无直接受害者，池的 LP 承担
清算抢先清算抵押不足的头寸被清算用户
三明治前置买入 + 受害者交易 + 后置卖出交易者
抢跑复制并提高 gas 抢先执行原交易者
回滚制造失败交易影响状态或清算协议与用户

MEV 不等于“攻击”。套利与清算在多数协议中是设计的一部分；三明治与抢跑才是需要防护的负外部性。

2. 用一个池子推演三明治 ​

javascript
// #region amm
const BPS = 10_000

export class ConstantProductPool {
  constructor(reserveA, reserveB, feeBps = 30) {
    if (reserveA <= 0 || reserveB <= 0) throw new Error('reserves must be positive')
    this.reserveA = reserveA
    this.reserveB = reserveB
    this.feeBps = feeBps
  }

  clone() {
    return new ConstantProductPool(this.reserveA, this.reserveB, this.feeBps)
  }

  get amountInWithFee() {
    return BPS - this.feeBps
  }

  /** 用 A 换 B 的报价 */
  quoteAForB(amountInA) {
    const amountInWithFee = amountInA * this.amountInWithFee
    return (
      (this.reserveB * amountInWithFee) /
      (this.reserveA * BPS + amountInWithFee)
    )
  }

  /** 用 B 换 A 的报价 */
  quoteBForA(amountInB) {
    const amountInWithFee = amountInB * this.amountInWithFee
    return (
      (this.reserveA * amountInWithFee) /
      (this.reserveB * BPS + amountInWithFee)
    )
  }

  swapAForB(amountInA) {
    const amountOutB = this.quoteAForB(amountInA)
    this.reserveA += amountInA
    this.reserveB -= amountOutB
    return amountOutB
  }

  swapBForA(amountInB) {
    const amountOutA = this.quoteBForA(amountInB)
    this.reserveB += amountInB
    this.reserveA -= amountOutA
    return amountOutA
  }

  get invariant() {
    return this.reserveA * this.reserveB
  }
}
// #endregion

// #region sandwich
/**
 * 三笔交易的经典三明治：
 * 1. 攻击者先买入，推高价格；
 * 2. 受害者按被推高的价格成交；
 * 3. 攻击者卖出，赚取差价。
 */
export function simulateSandwich(pool, { victimAmountIn, attackerAmountIn }) {
  const state = pool.clone()

  const attackerBought = state.swapAForB(attackerAmountIn)
  const victimOut = state.swapAForB(victimAmountIn)
  const attackerBackOut = state.swapBForA(attackerBought)

  return {
    attackerBought,
    victimOut,
    attackerBackOut,
    attackerProfitA: attackerBackOut - attackerAmountIn,
    finalReserveA: state.reserveA,
    finalReserveB: state.reserveB
  }
}

/** 没有攻击者时，受害者本应得到的结果 */
export function simulateHonest(pool, { victimAmountIn }) {
  return pool.clone().swapAForB(victimAmountIn)
}
// #endregion

// #region slippage
export class SlippageExceeded extends Error {
  constructor(amountOut, minAmountOut) {
    super(`SlippageExceeded: got ${amountOut}, minimum ${minAmountOut}`)
    this.name = 'SlippageExceeded'
    this.code = 'SlippageExceeded'
    this.amountOut = amountOut
    this.minAmountOut = minAmountOut
  }
}

/** 受害者的滑点保护：成交价低于下限就回滚整笔交易 */
export function swapWithSlippage(pool, amountInA, minAmountOut) {
  const amountOut = pool.quoteAForB(amountInA)
  if (amountOut < minAmountOut) {
    throw new SlippageExceeded(amountOut, minAmountOut)
  }
  return pool.swapAForB(amountInA)
}
// #endregion

3. 三笔交易的顺序决定结果 ​

text
攻击者买入 A→B   （推高 B 价格）
受害者买入 A→B   （以更差价格成交）
攻击者卖出 B→A   （赚取差价）
1
2
3

如果受害者先成交，攻击者只能后置卖出，收益模型完全不同。因此 MEV 的核心不是“会不会算”，而是“能不能排到前面”。

排序权属于区块生产者，这也是 PBS（Proposer-Builder Separation）要解决的问题。

效果与局限：

  • 能阻止“被夹”的成交。
  • 不能阻止攻击者制造失败交易、消耗 gas 或影响其他状态。
  • 下限设得太松仍然会被夹；设得太紧则正常波动也会失败。

5. 用户侧防护 ​

  • 使用聚合器或 RFQ，减少公开 mempool 暴露。
  • 设置合理滑点，不要用“无限滑点”。
  • 大额交易拆单或使用 TWAP。
  • 关注交易截止时间（deadline），避免旧交易被延迟执行。
  • 在 L2 或私有交易通道提交，降低被抢跑概率。

6. 协议侧防护 ​

  • 关键状态变更使用 commit-reveal。
  • 清算与拍卖使用批量拍卖或延迟执行。
  • 价格更新使用 TWAP / 多源预言机，避免单区块操纵。
  • 对同一区块内的异常顺序做监控与告警。
  • 重要参数变更走 timelock，减少抢跑窗口。

7. PBS 与角色分工 ​

角色职责
searcher寻找套利、清算与订单流机会
builder组装区块，选择交易顺序
relay在 proposer 与 builder 之间传递区块
proposer出块，获得区块奖励与 MEV 分成

PBS 把“排序”从共识层分离出来，降低 proposer 的技术门槛，但也引入 builder 集中化与订单流拍卖等新问题。

8. 私有交易与测试网 ​

  • 私有交易绕过公开 mempool，但仍有信任假设：中继方可能泄露或滥用。
  • 测试网上 MEV 价值很低，适合验证工具与监控，不适合评估真实收益。
  • 本示例只模拟本地池子，不接入任何真实交易通道。

10 条测试：

  • 报价与 swap 结果一致。
  • 手续费降低输出。
  • 三明治降低受害者输出、攻击者利润为正。
  • 前置交易越大，受害者损失越大。
  • 1% 滑点保护回滚；无保护时仍成交。
  • 手续费使 k 增长。
  • clone 不共享状态。
  • 零输入边界。

10. 常见坑 ​

  • 只算受害者损失：忽略攻击者 gas 成本与失败风险。
  • 认为滑点保护零成本：回滚交易仍然消耗 gas。
  • 用现货价格做清算：单区块价格操纵会放大 MEV。
  • 在公开 mempool 暴露大额交易：等于给 searcher 发信号。
  • 忽略 L2 排序器：L2 也有排序权与 MEV，只是形态不同。
  • 把套利等同于攻击：套利常常提升市场效率，防护目标应是负外部性。
