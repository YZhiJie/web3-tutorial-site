15 · EVM 内部与优化 ​

需进阶约 6 学时 前置：/advanced/07-solidity-patterns、/advanced/08-testing-local-chain验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 把一段字节码拆成操作码序列，读懂函数分发与 PUSH/JUMP 的基本模式。
  • 解释 storage slot、打包规则与 SSTORE 成本，判断哪些字段应该相邻。
  • 区分 calldata 与 memory 的复制成本，选择正确的参数位置。
  • 用真实测量比较优化前后的 gas，而不是凭直觉改写代码。
  • 说明每项优化的可读性代价，知道什么时候不该优化。

前置检查 ​

  • 已完成 07 · Solidity 进阶与合约模式 与 08 · 测试与本地链。
  • 能读懂 Hardhat 测试与 estimateGas。
  • 知道 storage、memory、calldata 三种数据位置。

本章示例位于 examples/15-evm-internals，包含 1 个合约、1 个反汇编器与 10 条测试。所有 gas 数字都来自本地 Hardhat Network 实测。

1. 先看字节码，再看源码 ​

部署后的合约只有字节码。最小阅读路径：

  1. 前几条指令通常是 PUSH1 0x80 PUSH1 0x40 MSTORE，建立空闲内存指针。
  2. 接着检查 CALLVALUE，非零则 REVERT，这是 payable 检查。
  3. 然后按 PUSH1 0x04 CALLDATASIZE LT 判断是否有 calldata，再取函数选择器。
  4. PUSH4 <selector> 与 DUP1、EQ、PUSH2 <dest>、JUMPI 构成函数分发。

一个最小反汇编器只需要正确处理 PUSH 的立即数宽度：

function isPush(opcode) {
  return opcode >= 0x60 && opcode <= 0x7f
}

function nameOf(opcode) {
  return OPCODES[opcode] ?? `UNKNOWN_0x${opcode.toString(16).padStart(2, '0')}`
}

export function disassemble(bytecode) {
  const hex = bytecode.replace(/^0x/, '').toLowerCase()
  const instructions = []

  for (let pc = 0; pc < hex.length; pc += 2) {
    const opcode = Number.parseInt(hex.slice(pc, pc + 2), 16)
    const name = nameOf(opcode)
    const instruction = { pc: pc / 2, opcode, name, pushData: null }

    if (isPush(opcode)) {
      const width = opcode - 0x5f
      instruction.pushData = hex.slice(pc + 2, pc + 2 + width * 2)
      pc += width * 2
    }

    instructions.push(instruction)
  }

  return instructions
}

export function countOpcodes(bytecode) {
  const counts = {}
  for (const instruction of disassemble(bytecode)) {
    counts[instruction.name] = (counts[instruction.name] ?? 0) + 1
  }
  return counts
}

元数据不是代码

字节码尾部有编译器追加的 CBOR 元数据，反汇编器会把它当成未知指令。做统计时可以按 ABI 或源码映射截断，不要据此判断合约行为。

2. Storage slot 与打包 ​

EVM 的 storage 是 2^256 个 32 字节槽。每个 SSTORE 都可能很贵，因此字段顺序直接决定成本：

solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title GasLab
/// @notice 用最小函数对比存储布局、calldata 与 storage 读取的 gas 差异。
contract GasLab {
    // #region storage-packing
    struct Unpacked {
        uint256 a;
        uint256 b;
        uint256 c;
    }

    struct Packed {
        uint128 a;
        uint128 b;
        uint64 c;
    }

    Unpacked public unpacked;
    Packed public packed;

    /// @notice 三个 uint256 各占一个 slot，需要 3 次 SSTORE
    function setUnpacked(uint256 a, uint256 b, uint256 c) external {
        unpacked = Unpacked(a, b, c);
    }

    /// @notice 两个 uint128 共用一个 slot，加上 uint64，总共 2 个 slot
    function setPacked(uint128 a, uint128 b, uint64 c) external {
        packed = Packed(a, b, c);
    }
    // #endregion

    // #region calldata-memory
    /// @notice calldata 按需读取，不复制到内存
    function sumCalldata(uint256[] calldata values) external pure returns (uint256 sum) {
        for (uint256 i = 0; i < values.length; i++) {
            sum += values[i];
        }
    }

    /// @notice memory 参数会先把 calldata 复制到内存
    function sumMemory(uint256[] memory values) external pure returns (uint256 sum) {
        for (uint256 i = 0; i < values.length; i++) {
            sum += values[i];
        }
    }
    // #endregion

    // #region storage-loop
    uint256[] public numbers;

    function loadNumbers(uint256[] calldata values) external {
        numbers = values;
    }

    /// @notice 每次循环都重新读取 numbers.length
    function sumStorage() external view returns (uint256 sum) {
        for (uint256 i = 0; i < numbers.length; i++) {
            sum += numbers[i];
        }
    }

    /// @notice 把 length 与 storage 引用缓存到局部变量
    function sumCached() external view returns (uint256 sum) {
        uint256[] storage values = numbers;
        uint256 length = values.length;
        for (uint256 i = 0; i < length; i++) {
            sum += values[i];
        }
    }
    // #endregion

    // #region custom-errors
    error Unauthorized();

    function requireString(address account) external pure {
        require(account != address(0), "GasLab: unauthorized");
    }

    function requireCustomError(address account) external pure {
        if (account == address(0)) revert Unauthorized();
    }
    // #endregion
}

  • Unpacked 三个 uint256 各占一个 slot，写入需要 3 次 SSTORE。
  • Packed 两个 uint128 共用一个 slot，uint64 再用一个，写入 2 个 slot。

打包的代价

打包会让读写多一步掩码与位移，字段太碎时运行时反而更贵。先测量，再决定。

calldata 直接按需读取；memory 会先把整个数组复制到内存。20 个元素时实测：

函数gas
sumCalldata28860
sumMemory29913

差距不大，但数组越大、循环越短，复制成本占比越明显。原则：

  • 只读的外部输入优先用 calldata。
  • 需要在内存里修改、返回或多次随机访问时才用 memory。
  • storage 引用适合需要写回的场景，但每次读写仍然是 SLOAD/SSTORE。

            sum += numbers[i];
        }
    }

    /// @notice 把 length 与 storage 引用缓存到局部变量
    function sumCached() external view returns (uint256 sum) {
        uint256[] storage values = numbers;
        uint256 length = values.length;
        for (uint256 i = 0; i < length; i++) {
            sum += values[i];
        }
    }

    // #region custom-errors
    error Unauthorized();

    function requireString(address account) external pure {
        require(account != address(0), "GasLab: unauthorized");
    }

    function requireCustomError(address account) external pure {
        if (account == address(0)) revert Unauthorized();
    }

自定义错误相比字符串：

  • 字节码更短：只编码 4 字节选择器，不需要存储长字符串。
  • 前端更容易精确处理：可以按错误选择器分支。
  • 但错误信息可读性下降，需要在 ABI 或文档中补说明。

Solidity 编译器会把错误选择器左移后编码进 REVERT 数据。测试里检查的是选择器前缀，而不是完整 4 字节，因为优化器可能用位移指令复用常量。

6. 如何做一份可信的 gas 报告 ​

推荐流程：

  1. 固定编译器版本、optimizer runs、Hardhat 版本与网络配置。
  2. 每个对比用独立 fixture，避免冷热状态污染。
  3. 同时记录 estimateGas 与真实交易收据的 gasUsed，并注明用的是哪一个。
  4. 至少跑 3 次，报告区间而不是单点。
  5. 把“可读性代价”和“维护风险”写进结论。

示例测试直接打印数字并断言相对关系：

10 条测试覆盖：

  • 打包存储的 gas 优势与差值下限。
  • calldata 与 memory 的成本及结果一致性。
  • storage 缓存与直接读取的成本及结果一致性。
  • 自定义错误选择器存在于字节码。
  • 反汇编的 PUSH1/PUSH2、未知操作码与频次统计。

7. 常见坑 ​

  • 用部署字节码判断运行时行为：要看 deployedBytecode，不是 bytecode。
  • 把 estimateGas 当成实际 gas：它包含安全边际，真实值看收据。
  • 忽略冷热访问：同一 slot 第一次访问和后续访问价格不同。
  • 只优化一次调用：高频路径与一次性初始化要分开评估。
  • 为了省几百 gas 牺牲可读性：优先优化循环、存储布局与外部调用，不要手写晦涩汇编。
  • 忘记 optimizer runs 影响：runs 越大，运行时代码越贵、部署代码越大，反之亦然。

8. 练习题 ​

  1. 给 GasLab 增加一个 uint64 + uint64 + uint128 的结构，比较槽数与 gas。
  2. 用真实交易收据的 gasUsed 重做一次对比，说明与 estimateGas 的差异。
  3. 给反汇编器增加源码映射或函数选择器识别，输出每个函数的入口 pc。
  4. 写一个脚本，统计部署字节码中 PUSH0 与 PUSH1 0x00 的出现次数。
  5. 选一段真实合约的 deployedBytecode，找出所有 SSTORE 并解释对应源码。
