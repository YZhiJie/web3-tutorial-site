教学实现

本章的 NFT、市场和版税代码是教学简化版，未经审计不要用于真实资产；生产项目应使用审计过的 ERC-721 实现，并明确托管、版税和失败退款规则。

练习 1：给 MiniNFT 增加 burn

在 MiniNFT 的转移区域增加：

solidity
function burn(uint256 tokenId) external {
    address tokenOwner = ownerOf(tokenId);

    bool authorized =
        msg.sender == tokenOwner ||
        _tokenApprovals[tokenId] == msg.sender ||
        isApprovedForAll(tokenOwner, msg.sender);
    require(authorized, 'not authorized');

    // 先清授权，再删所有权与余额
    _tokenApprovals[tokenId] = address(0);
    _balances[tokenOwner] -= 1;
    delete _owners[tokenId];

    emit Transfer(tokenOwner, address(0), tokenId);
}

要点：

  • ownerOf(tokenId) 本身会拒绝不存在的 token，所以 burn 不需要额外检查存在性。
  • 必须同时支持 owner、单 token 授权、全局 operator 三种调用者。
  • 先清空 _tokenApprovals，避免 tokenId 未来被复用（本示例递增不复用，但生产合约可能复用）时继承旧授权。
  • ERC-721 标准用 Transfer(owner, address(0), tokenId) 表示销毁，不要只 delete 而不发事件。
  • 销毁后 tokenURI 查询会 revert，前端应把已销毁 token 当作不存在。
练习 2：实现 safeTransferFrom 与 onERC721Received 检查

在 MiniNFT.sol 顶部增加接口：

interface IERC721Receiver {
    function onERC721Received(
        address operator,
        address from,
        uint256 tokenId,
        bytes calldata data

}

在转移区域增加两个重载：

solidity
function safeTransferFrom(address from, address to, uint256 tokenId) external {
    safeTransferFrom(from, to, tokenId, '');
}

function safeTransferFrom(
    address from,
    address to,
    uint256 tokenId,
    bytes memory data
) public {
    transferFrom(from, to, tokenId);

    if (to.code.length > 0) {
        try IERC721Receiver(to).onERC721Received(msg.sender, from, tokenId, data)
        returns (bytes4 selector) {
            if (selector != IERC721Receiver.onERC721Received.selector) {
                revert('unsafe recipient');
            }
        } catch {
            revert('unsafe recipient');
        }
    }
}

要点：

  • EOA 没有代码，to.code.length == 0，直接跳过回调。
  • 合约接收方必须返回 IERC721Receiver.onERC721Received.selector，也就是 0x150b7a02。
  • 返回错误 selector、没有实现回调、回调 revert，都会被 catch 后转成统一的 unsafe recipient，并且整笔转移回滚。
  • 如果先转移、后检查，检查失败时依靠 revert 把转移也回滚；不要写成“检查失败只记录日志”。
  • 生产实现还应实现 ERC-165，并区分 safeTransferFrom 与普通 transferFrom 的语义。
练习 3：改成非托管市场，并测试卖家成交前撤销授权

把 FixedPriceMarket 的 list、buy、cancel 改成下面这样，市场不再持有 NFT：

solidity
function list(uint256 tokenId, uint256 price) external {
    if (listings[tokenId].active) revert AlreadyListed(tokenId);
    if (nft.ownerOf(tokenId) != msg.sender) revert NotTokenOwner(msg.sender, tokenId);
    if (price == 0) revert InvalidPrice();

    bool approved =
        nft.getApproved(tokenId) == address(this) ||
        nft.isApprovedForAll(msg.sender, address(this));
    if (!approved) revert MarketNotApproved(tokenId);

    listings[tokenId] = Listing({seller: msg.sender, price: price, active: true});
    emit Listed(tokenId, msg.sender, price);
}

function buy(uint256 tokenId) external payable {
    Listing memory listing = listings[tokenId];
    if (!listing.active) revert NotListed(tokenId);
    if (msg.sender == listing.seller) revert CannotBuyOwnListing();
    if (msg.value != listing.price) revert WrongPayment(listing.price, msg.value);

    // 先关单，再做外部调用
    listings[tokenId].active = false;

    // 成交时重新检查：卖家可能已经转走 NFT 或撤销授权
    if (nft.ownerOf(tokenId) != listing.seller) {
        revert NotTokenOwner(listing.seller, tokenId);
    }
    bool approved =
        nft.getApproved(tokenId) == address(this) ||
        nft.isApprovedForAll(listing.seller, address(this));
    if (!approved) revert MarketNotApproved(tokenId);

    uint256 fee = (listing.price * FEE_BPS) / 10_000;
    uint256 proceeds = listing.price - fee;

    nft.transferFrom(listing.seller, msg.sender, tokenId);

    (bool sellerOk, ) = listing.seller.call{value: proceeds}('');
    require(sellerOk, 'seller transfer failed');

    (bool feeOk, ) = feeRecipient.call{value: fee}('');
    require(feeOk, 'fee transfer failed');

    emit Sold(tokenId, msg.sender, listing.price, fee);
}

function cancel(uint256 tokenId) external {
    Listing memory listing = listings[tokenId];
    if (!listing.active) revert NotListed(tokenId);
    if (msg.sender != listing.seller) revert NotSeller(msg.sender);

    // 非托管：只关单，不需要把 NFT 转回来
    listings[tokenId].active = false;
    emit Cancelled(tokenId, listing.seller);
}

要点：

  • 非托管降低了平台跑路和合约被攻破时的 NFT 托管风险，但成交不再是“市场一定能交付”。
  • 卖家可以在买家交易上链前撤销授权或转走 NFT，买家交易会 revert，gas 由买家承担。这是非托管市场的固有竞态。
  • 缓解方式：签名挂单 + 截止时间、提高成交原子性、监控授权变化、对失败交易补偿，或者对大额交易使用托管/escrow。
  • 原有“上架会把 NFT 托管到市场”和“取消后 NFT 退回”的测试要同步改成“上架后 NFT 仍在卖家手里”，否则测试会失败。
  • 现有测试 fixture 已在上架前 approve(market)，所以 list 的授权检查能通过。

要点：

  • 如果只做练习 4、没有做练习 3，buy 里的 NFT 仍在市场托管，转账那一行要写成 nft.transferFrom(address(this), msg.sender, tokenId)；如果同时做了练习 3，才用 listing.seller。
  • 本练习把平台费与版税都按成交总价计算：2.5% + 1%，卖家拿到剩余的 96.5%。
  • 先算两笔费用、再算卖家所得，并且卖家拿“余数”，可以把整数除法的舍入尘埃留给卖家，避免合约里残留 wei。
  • 顺序不影响三笔金额，但必须先确认 fee + royalty <= price。本例是固定常数，天然满足；如果费率可由治理修改，必须加上限检查。
  • 如果版税按“卖家所得”计算，金额会略低，而且和 EIP-2981 的常见语义不一致。团队必须把“按总价还是按净额”写进规格和测试。
  • EIP-2981 只定义查询接口，不强制市场支付。真实市场应读取 royaltyInfo(tokenId, salePrice)，并处理返回接收方为零地址、版税过高、接收方拒收 ETH 等情况。
  • 对外部收款方使用 call 并检查返回值；如果收款方可能是不可信合约，考虑 pull payment 或 0xSplits 之类的分账合约，避免一笔失败导致整单成交回滚。
  • 这是教学实现，不是生产级版税系统。
