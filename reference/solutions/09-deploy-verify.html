练习 1：增加 deployAndTransfer，部署后把部分代币转给买家

SimpleToken 目前没有转账函数，先补一个最小实现：

solidity
function transfer(address to, uint256 amount) external returns (bool) {
    require(to != address(0), 'zero address');
    require(balanceOf[msg.sender] >= amount, 'insufficient balance');

    balanceOf[msg.sender] -= amount;
    balanceOf[to] += amount;
    emit Transfer(msg.sender, to, amount);
    return true;
}

把原来的部署逻辑抽成内部函数：

solidity
function _deploy(
    bytes32 salt,
    string memory name,
    string memory symbol,
    uint256 supply,
    address holder
) internal returns (address token) {
    address predicted = predictAddress(salt, name, symbol, supply, holder);
    if (predicted.code.length > 0) revert AlreadyDeployed(predicted);

    bytes memory initCode = abi.encodePacked(
        type(SimpleToken).creationCode,
        abi.encode(name, symbol, supply, holder)
    );

    assembly {
        token := create2(0, add(initCode, 0x20), mload(initCode), salt)
    }
    if (token == address(0)) revert DeployFailed();

    emit Deployed(token, salt, msg.sender);
}

新增分发函数：

solidity
function deployAndTransfer(
    bytes32 salt,
    string memory name,
    string memory symbol,
    uint256 supply,
    address holder,
    address buyer,
    uint256 amount
) external returns (address token) {
    if (holder == address(0) || buyer == address(0)) revert ZeroAddress();
    if (amount > supply) revert InvalidAmount(supply, amount);

    // 初始供应先给工厂，工厂才有余额执行 transfer
    token = _deploy(salt, name, symbol, supply, address(this));

    require(SimpleToken(token).transfer(buyer, amount), 'buyer transfer failed');
    if (supply > amount) {
        require(SimpleToken(token).transfer(holder, supply - amount), 'holder transfer failed');
    }
}

测试：

ts
it('deployAndTransfer 把部分代币转给买家，其余留给持有人', async () => {
  const [deployer, buyer] = await ethers.getSigners()
  const factory = await ethers.deployContract('DeterministicFactory')
  await factory.waitForDeployment()

  const amount = ethers.parseEther('100')
  const predicted = await factory.predictAddress(
    SALT_A,
    NAME,
    SYMBOL,
    SUPPLY,
    await factory.getAddress()
  )

  await factory.deployAndTransfer(
    SALT_A,
    NAME,
    SYMBOL,
    SUPPLY,
    deployer.address,
    buyer.address,
    amount
  )

  const token = await ethers.getContractAt('SimpleToken', predicted)
  expect(await token.balanceOf(buyer.address)).to.equal(amount)
  expect(await token.balanceOf(deployer.address)).to.equal(SUPPLY - amount)
})

要点：

  • 初始持有人必须是工厂自己，否则工厂没有代币可以转给买家。

新增 scripts/check-addresses.ts：

ts
import fs from 'node:fs'
import { ethers } from 'ethers'

type AddressBook = Record<string, Record<string, string>>

async function main() {
  const book = JSON.parse(fs.readFileSync('deployments.json', 'utf8')) as AddressBook
  let failed = false

  for (const [chainId, entries] of Object.entries(book)) {
    const rpcUrl = process.env[`RPC_URL_${chainId}`]
    if (!rpcUrl) {
      console.error(`chain ${chainId}: 缺少 RPC_URL_${chainId}`)
      failed = true
      continue
    }

    const provider = new ethers.JsonRpcProvider(rpcUrl)

    for (const [name, address] of Object.entries(entries)) {
      const code = await provider.getCode(address)
      const ok = code !== '0x'
      console.log(`${chainId} ${name} ${address} ${ok ? 'OK' : 'NO_CODE'}`)
      if (!ok) failed = true
    }
  }

  if (failed) process.exitCode = 1
}

main().catch((error) => {
  console.error(error)
  process.exitCode = 1
})

要点：

  • 地址簿按链 ID 分组，避免把 Sepolia 地址贴到本地链。
  • 只检查 getCode，不调用业务函数，脚本可以安全重跑。
  • 任意一个地址返回 0x 就以非零状态退出，方便放进 CI 或部署后检查。
  • RPC URL 从环境变量读取；地址文件可以提交，RPC 与私钥不能提交。
  • Hardhat 的 hardhat run 只负责执行脚本，真正的链选择由脚本里的 JsonRpcProvider 决定。
练习 3：为什么 CREATE2 地址与交易发送者的 nonce 无关

CREATE2 的公式是：

text
address = keccak256(0xff ++ factory ++ salt ++ keccak256(initCode))[12:]
1

四个输入里没有 EOA 的 nonce，只有：

  1. 执行 create2 的工厂合约地址 factory；
  2. 调用方传入的 salt；
  3. 完整 init code 的哈希，包含构造参数。

nonce 只影响 CREATE 的地址，因为 CREATE 的公式是 keccak256(rlp(sender, nonce))。在 CREATE2 里，factory 一旦部署完成，地址就固定了；之后工厂本身发多少交易、nonce 是多少，都不会改变 create2 的结果。

需要注意的间接影响：

  • 工厂合约本身如果是用 CREATE 部署的，那么部署者的 nonce 会改变工厂地址，从而间接改变 CREATE2 结果。
  • 如果工厂是用 CREATE2 部署的，工厂地址也可以完全确定，整条链上的目标地址就能提前算出来。
  • msg.sender 在构造函数里是工厂地址，不是最初发起部署的 EOA。写初始化逻辑时不要把它当成用户地址。
练习 4：同一个 salt 在两条链上部署，地址是否相同

操作步骤：

bash

# 终端 2：本地部署

把两次输出的 factory 与 token 记到地址簿，然后比较。

结论分两种情况：

  • 工厂地址相同、构造参数相同、salt 相同：token 地址一定相同。CREATE2 公式里没有 chainId，两条链只是各自执行同样的字节码，算出来的地址自然一致。
  • 工厂地址不同：token 地址通常不同。deploy:local 与 deploy:sepolia 都是用 CREATE 部署工厂，工厂地址取决于部署者地址与 nonce；两条链上的 nonce 不一定相同，工厂地址就可能不同。

所以“同一个 salt”不是跨链同地址的充分条件，完整条件是：

text
相同 factory 地址 + 相同 salt + 相同 init code
1

如果业务真的需要跨链同地址，应把工厂本身也用 CREATE2 部署，或者保证工厂在每条链上都由同一地址、同一 nonce 创建。地址相同不代表状态相同：两条链上的合约各自独立，资产不能跨链共用。
