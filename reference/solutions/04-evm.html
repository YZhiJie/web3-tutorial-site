练习 1：连续调用两次 increment，两次 gasUsed 相同吗？

不相同。首次把存储槽从 0 写成 1，成本明显高于第二次从 1 写成 2。用 Hardhat 控制台实测：

bash
pnpm --filter @web3-ex/04-counter exec hardhat console
1
js
const factory = await ethers.getContractFactory('Counter')
const counter = await factory.deploy()
await counter.waitForDeployment()

const first = await (await counter.increment()).wait()
const second = await (await counter.increment()).wait()

console.log('first:', first.gasUsed.toString())
console.log('second:', second.gasUsed.toString())
console.log('number:', (await counter.number()).toString())

练习 2：让 setNumber 拒绝超过 100 的值，并补测试

在 examples/04-counter/contracts/Counter.sol 中增加自定义错误，并在 setNumber 里先检查权限、再检查范围：

solidity
error ValueTooLarge(uint256 value, uint256 max);

function setNumber(uint256 newValue) external {
    if (msg.sender != owner) revert NotOwner(msg.sender);
    if (newValue > 100) revert ValueTooLarge(newValue, 100);

    uint256 oldValue = _number;
    _number = newValue;
    emit NumberChanged(oldValue, newValue, msg.sender);
}

it('setNumber 拒绝超过 100 的值', async () => {
  const { counter, owner } = await deployCounter()

  await expect(counter.setNumber(101))
    .to.be.revertedWithCustomError(counter, 'ValueTooLarge')
    .withArgs(101n, 100n)

  // 边界值 100 仍然允许
  await expect(counter.setNumber(100))
    .to.emit(counter, 'NumberChanged')
    .withArgs(0n, 100n, owner.address)

  expect(await counter.number()).to.equal(100n)
})

练习 3：找出 NumberChanged 事件，三个 indexed 参数是什么？

NumberChanged 的三个参数全部带 indexed，因此它们都进入 topics：

solidity
event NumberChanged(
    uint256 indexed oldValue,
    uint256 indexed newValue,
    address indexed operator
);

也可以直接在区块浏览器的 Logs 标签页查看。各位置含义：

位置内容
topics[0]事件签名哈希 0xdba7ef19f2b4e0103786d473d3d310e0ab284d41e20aaaa30470dc9d4fe5b408
topics[1]oldValue，uint256 的十六进制
topics[2]newValue，uint256 的十六进制
topics[3]operator，发起调用的地址（32 字节，前 12 字节补 0）
data0x，因为该事件没有非 indexed 参数

indexed 参数适合按地址或数值过滤；但被索引的 uint256 只能精确匹配，不能做范围查询。需要范围筛选时，应把值放在非索引参数里或使用链下索引服务。

练习 4：用 viem getContractEvents 读取最近 5 条事件并按 newValue 排序

把下面脚本保存为 examples/06-dapp-vue/recent-events.mjs（该工程已经依赖 viem），然后传入本地部署地址运行：

js
import { createPublicClient, http, parseAbi } from 'viem'
import { hardhat } from 'viem/chains'

const address = process.env.COUNTER_ADDRESS
if (!address) throw new Error('请设置 COUNTER_ADDRESS')

const abi = parseAbi([
  'event NumberChanged(uint256 indexed oldValue, uint256 indexed newValue, address indexed operator)'
])

const client = createPublicClient({
  chain: hardhat,
  transport: http('http://127.0.0.1:8545')
})

const logs = await client.getContractEvents({
  address,
  abi,
  eventName: 'NumberChanged',
  fromBlock: 0n,
  toBlock: 'latest'
})

const recentFive = logs
  .slice(-5)
  .sort((a, b) => {
    const left = a.args.newValue
    const right = b.args.newValue
    return left < right ? -1 : left > right ? 1 : 0
  })

console.log(
  recentFive.map((log) => ({
    block: log.blockNumber,
    oldValue: log.args.oldValue,
    newValue: log.args.newValue,
    operator: log.args.operator
  }))
)

说明：

  • fromBlock: 0n 只适合本地链。Sepolia 上应改为最近的区块范围，否则 RPC 可能直接拒绝大区间查询。
  • getContractEvents 返回的是历史日志数组，不会像 watchContractEvent 那样持续推送。
  • uint256 解码后是 bigint，排序时不要先转 Number，否则超大值会丢精度。
  • 先取最近 5 条再按 newValue 排序；如果先排序再取尾部，语义会变成“值最大的 5 条”。
