路径中只有最后一段 index 变化，前四段固定：44' 是 BIP-44，60' 是以太坊币种，第一个 0' 是账户索引，第二个 0 表示外部链（收款地址）。换一个 index 就是另一个私钥、另一个地址，但都来自同一个助记词。

练习 2：修改 EIP-712 的 chainId 后，验签结果如何变化？

在 examples/02-wallet-signing 新建一个临时脚本（例如 domain-check.mjs）：

js
import { verifyTypedData } from 'ethers'
import {
  TEST_MNEMONIC,
  deriveAccount,
  loginDomain,
  loginTypes,
  signLogin
} from './src/wallet.mjs'

const { privateKey, address } = deriveAccount(TEST_MNEMONIC, 0)
const message = { user: 'alice', nonce: 1n }
const { signature } = await signLogin(privateKey, message)

const sameChain = verifyTypedData(loginDomain, loginTypes, message, signature)
const otherChain = verifyTypedData(
  { ...loginDomain, chainId: 1 },
  loginTypes,
  message,
  signature
)

console.log('原 domain 恢复地址:', sameChain, sameChain === address)
console.log('chainId=1 恢复地址:', otherChain, otherChain === address)

结果：原 domain 恢复出的地址等于签名者；把 chainId 改成 1 后，verifyTypedData 仍会返回一个地址，但它不等于签名者。这说明签名已经把 chainId 纳入摘要，换链后旧签名不能直接复用。

因此服务端验签必须使用与签名时完全一致的 domain（name、version、chainId、verifyingContract），不能只校验“能恢复出一个地址”。

练习 3：给定消息与签名，恢复地址并拒绝被篡改的消息

在示例中新增一个校验函数（保存为 src/recover.mjs）：

js
import { verifyMessage } from 'ethers'

export function recoverSigner(message, signature, expectedAddress) {
  const recovered = verifyMessage(message, signature)

  if (recovered !== expectedAddress) {
    throw new Error(`签名不匹配：恢复出 ${recovered}，期望 ${expectedAddress}`)
  }

  return recovered
}

  const { privateKey, address } = deriveAccount(TEST_MNEMONIC, 0)
  const { signature } = await signText(privateKey, '原始消息')

  assert.equal(recoverSigner('原始消息', signature, address), address)

    () => recoverSigner('原始消息（被篡改）', signature, address),

练习 4：给一份真实签名请求标注链、合约、方法与金额

这道题没有标准答案，重点是养成逐项核对的习惯。打开钱包的签名弹窗后，按下面的清单标注：

检查项在哪里看需要确认什么
链弹窗顶部的网络名称，或请求里的 chainId是否是你预期的网络，例如 Sepolia 11155111、本地 Hardhat 31337
合约“Contract”“Interacting with”或请求中的 to 地址地址是否与官网/文档公布的一致，不要只看首尾
方法函数名与参数列表，例如 approve、transferFrom、permit方法是否与当前操作相符；登录不应出现转账授权
金额value、amount、allowance 等字段单位是 ETH 还是代币；是否为无限授权；接收方是否为你本人
费用/nonceGas、Max fee、Nonce（交易类请求）费用是否异常，nonce 是否连续

如果钱包只显示一串十六进制，不要盲签。先把 calldata 拿到区块浏览器或 Tenderly 解码，确认选择器对应的函数与参数。任何要求输入助记词来“验证/升级/领取”的页面都应直接关闭。
