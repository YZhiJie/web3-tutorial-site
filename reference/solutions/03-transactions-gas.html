练习 1：用相同 nonce 发送第二笔交易，会看到什么错误？

先启动 Hardhat 控制台：

bash
pnpm --filter @web3-ex/03-gas-lab exec hardhat console
1

关闭自动挖矿，让第一笔交易停留在交易池，然后用相同 nonce 发第二笔：

js
const [sender] = await ethers.getSigners()
await network.provider.send('evm_setAutomine', [false])

const nonce = await ethers.provider.getTransactionCount(sender.address, 'latest')
const first = await sender.sendTransaction({ to: sender.address, value: 1n, nonce })
const second = await sender.sendTransaction({ to: sender.address, value: 2n, nonce })

第二笔会失败，实测错误是：

text
ProviderError: Replacement transaction underpriced. A gasPrice/maxFeePerGas of at least 3025000000 is necessary to replace the existing transaction with nonce 0.
1

含义：同一 nonce 的交易不是“再发一笔”，而是在竞争替换旧交易；费用涨幅不足时节点拒绝。阈值会随 baseFee 变化，不是固定值。

恢复自动挖矿并清理现场：

js
await network.provider.send('evm_mine')
await network.provider.send('evm_setAutomine', [true])
1
2

如果第一笔已经被打包，再发相同 nonce 则会得到 nonce has already been used / nonce too low 一类错误。替换交易时应把 maxFeePerGas 和 maxPriorityFeePerGas 都提高（常见做法至少 +10%）。

练习 2：pushBatch(1) 与 pushBatch(5) 的单笔平均 Gas

在 examples/03-gas-lab/test/GasLab.test.ts 中追加一个用例。为了排除前一次写入的冷热状态影响，用两个新部署的实例分别测试：

ts
it('对比 pushBatch(1) 与 pushBatch(5) 的单笔平均 Gas', async () => {
  const one = await deploy()
  const five = await deploy()

  const oneReceipt = await (await one.pushBatch(1)).wait()
  const fiveReceipt = await (await five.pushBatch(5)).wait()

  console.log('pushBatch(1) 单笔平均:', oneReceipt!.gasUsed.toString())
  console.log('pushBatch(5) 单笔平均:', (fiveReceipt!.gasUsed / 5n).toString())

  expect(fiveReceipt!.gasUsed / 5n).to.be.lessThan(oneReceipt!.gasUsed)
})

原因：每笔交易都有固定的基础开销（nonce、签名验证、打包等）。批量写入把固定开销摊到多项上，所以单笔平均明显更低；但总 Gas 仍然随写入项数增长，不能无限批量。

具体数值会随编译器版本、优化器与冷热状态变化，结论应比较相对大小，不要写死绝对值。

练习 3：找一笔失败交易，记录 status、gasUsed 与 revert 原因

在 Sepolia 区块浏览器搜索一笔状态为 Fail 的交易，按下表记录：

字段示例位置说明
status交易详情页的 Status0 表示执行失败，但交易已上链
gasUsedGas Used / Transaction Fee失败也会消耗，实际扣费是 gasUsed × effectiveGasPrice
revert 原因Revert Reason、Internal Txns 或 Tenderly 解码常见如 ERC20: transfer amount exceeds balance、execution reverted

如果浏览器没有直接展示原因，可以用脚本确认收据，再用 Tenderly 或 cast run 回放：

ts
import { JsonRpcProvider } from 'ethers'

const provider = new JsonRpcProvider(process.env.SEPOLIA_RPC_URL)
const receipt = await provider.getTransactionReceipt(txHash)

console.log(receipt?.status) // 0 = 失败，1 = 成功
console.log(receipt?.gasUsed.toString())
console.log(receipt?.logs) // 失败交易通常没有有效业务日志

练习 4：给定 baseFee 与小费，计算 maxFeePerGas
ts
export function suggestMaxFeePerGas(
  baseFeeWei: bigint,
  priorityFeeWei: bigint
): bigint {
  return baseFeeWei * 2n + priorityFeeWei
}

例如 baseFee 为 20 gwei、小费为 2 gwei：

ts
import assert from 'node:assert/strict'

const gwei = 1_000_000_000n
assert.equal(
  suggestMaxFeePerGas(20n * gwei, 2n * gwei),
  42n * gwei
)

有效 Gas 价格是 min(maxFeePerGas, baseFee + maxPriorityFeePerGas)。baseFee 每个区块最多上涨约 12.5%，留出 2 倍余量可以让交易在拥堵时继续被接受，避免因 baseFee 超过上限而长期 pending。

余量不是越大越好：maxFeePerGas 是上限，实际扣费仍按 baseFee + 小费 计算；但钱包通常会按上限冻结余额，设得过高会临时占用更多可用余额。若交易仍然卡住，应使用相同 nonce 提高费用替换。
