练习 1：给 AuditVaultFixed 增加暂停功能

在 contracts/AuditVaultFixed.sol 中增加状态、修饰器和开关函数：

solidity
bool public paused;

error IsPaused();

event Paused(address indexed by);
event Unpaused(address indexed by);

modifier whenNotPaused() {
    if (paused) revert IsPaused();
    _;
}

function pause() external onlyOwner {
    paused = true;
    emit Paused(msg.sender);
}

function unpause() external onlyOwner {
    paused = false;
    emit Unpaused(msg.sender);
}

练习 2：把 setFeeRecipient 改成两步转移

把原来的单步 setter 替换为“提案 + 接受”：

solidity
address public pendingFeeRecipient;

event FeeRecipientProposed(address indexed recipient);
event FeeRecipientUpdated(address indexed recipient);

error NotPendingRecipient();

function proposeFeeRecipient(address recipient) external onlyOwner {
    if (recipient == address(0)) revert ZeroAddress();
    pendingFeeRecipient = recipient;
    emit FeeRecipientProposed(recipient);
}

function acceptFeeRecipient() external {
    if (msg.sender != pendingFeeRecipient) revert NotPendingRecipient();

    feeRecipient = msg.sender;
    pendingFeeRecipient = address(0);

    emit FeeRecipientUpdated(msg.sender);
}

练习 3：给审计规则增加跨行“未检查 call 返回值”检测

原来的逐行判断遇到跨行调用会漏报。用“语句缓冲”把多行拼成一条语句再判断，并排除 ==、!=、>= 等比较运算：

js
function findUncheckedCalls(source) {
  const findings = []
  let statement = ''
  let startLine = 1

  source.split('\n').forEach((line, index) => {
    if (statement === '') startLine = index + 1
    statement += `${line}\n`

    // 只在语句结束时判断；不处理没有分号的宏或注释块
    if (!/[;}]\s*$/.test(line)) return

    const callPattern = /\.call\s*(?:\{[^}]*\})?\s*\(/
    const assignmentPattern = /(?<![=!<>])=(?!=)\s*[^;]*\.call\s*(?:\{[^}]*\})?\s*\(/

    if (callPattern.test(statement) && !assignmentPattern.test(statement)) {
      findings.push({
        id: 'unchecked-call',
        severity: 'high',
        message: `第 ${startLine} 行附近的低层 call 返回值未赋给变量`
      })
    }

    statement = ''
  })

  return findings
}

练习 4：为金库写“总余额等于所有用户余额之和”的不变量测试

这个不变量只在“金库没有其他资金流入、没有额外收益”时成立。测试用固定版金库：

ts
it('合约余额等于所有用户余额之和', async () => {
  const { vault, deployer, victim, other } = await loadFixture(deployFixed)
  const vaultAddress = await vault.getAddress()
  const depositors = [deployer, victim, other]

  await vault.connect(victim).deposit({ value: ethers.parseEther('2') })
  await vault.connect(other).deposit({ value: ethers.parseEther('1') })
  await vault.connect(deployer).deposit({ value: ethers.parseEther('3') })

  const sumBalances = async () => {
    const balances = await Promise.all(
      depositors.map((account) => vault.balances(account.address))
    )
    return balances.reduce((total, balance) => total + balance, 0n)
  }

  expect(await ethers.provider.getBalance(vaultAddress)).to.equal(await sumBalances())

  await vault.connect(victim).withdrawAll()

  expect(await ethers.provider.getBalance(vaultAddress)).to.equal(await sumBalances())
})

练习 5：按模板写一页审计报告（含 PoC 与修复建议）

下面是一份基于本章靶场的 1 页报告示例。数字全部来自现有测试。

标题与结论 ​

审计对象： AuditVault（教学靶场） 结论： 存在 1 个 Critical 与 1 个 Medium，修复前不可用于任何持有真实资金的场景。

范围与威胁模型 ​

  • 范围：contracts/AuditVault.sol 的 deposit、withdrawAll、setFeeRecipient；不包含修复版与攻击合约。
  • 攻击者能力：可部署合约、可存入任意金额、可在 receive 中重入、可调用任意 external 函数。
  • 不在范围：私钥泄露、链下前端、经济模型与治理。

Critical：withdrawAll 重入可盗取他人资金 ​

  • 影响： 攻击者存入 1 ETH 后可提取 2 ETH，金库余额从 6 ETH 降到 4 ETH。
  • 位置： AuditVault.withdrawAll。
  • 前置条件： 金库中已有其他用户存款；攻击者用合约地址调用。
  • PoC： test/Audit.test.ts 中的“漏洞版：攻击者用 1 ETH 抽走 2 ETH”。
    1. 受害者存入 5 ETH；
    2. 攻击合约存入 1 ETH，调用 withdrawAll；
    3. receive 中再次调用 withdrawAll，此时余额尚未清零；
    4. 攻击合约余额变为 2 ETH，金库余额变为 4 ETH。
  • 根因： 先执行外部 call，后更新 balances[msg.sender]，违反 Checks-Effects-Interactions。
  • 修复： 先清零余额，再加 nonReentrant，并检查 amount == 0；见 AuditVaultFixed.withdrawAll。

Medium：setFeeRecipient 缺少访问控制 ​

  • 影响： 任意地址都能改收款地址，可能导致费用被重定向。
  • 位置： AuditVault.setFeeRecipient。
  • 前置条件： 无，任何外部账户均可调用。
  • PoC： “漏洞版：任何人都能改收款地址”测试直接以普通用户调用并成功。
  • 根因： 函数声明为 external 但没有 onlyOwner。
  • 修复： 增加 onlyOwner 与零地址检查；生产环境进一步改成两步转移并走多签。

回归与验证 ​

bash
pnpm --filter @web3-ex/18-audit test
1

修复版必须同时通过：

  • 攻击交易回滚，金库余额保持 5 ETH；
  • 正常用户仍能提取；
  • 非 owner 修改收款地址失败；
  • 零地址被拒绝。

工具与未覆盖范围 ​

  • 本章示例流程没有集成 Slither/Foundry，未做形式化验证；正则规则只覆盖少量模式。
  • 未覆盖业务语义、经济模型、跨合约组合风险与升级治理。
  • 报告结论只针对本靶场，不能外推到其他合约。

报告写完后要附上修复提交与回归记录；没有 PoC 的问题只能标为“怀疑”，不能写成“确认”。
