06 · 第一个 dApp ​

零基础约 8 学时 前置：/guide/05-solidity-basics验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 画出 dApp 从点击按钮到链上确认的完整调用链。
  • 用 viem 连接浏览器钱包、读取合约状态、发送写交易。
  • 监听合约事件，并在交易确认后刷新界面。
  • 把本地 Hardhat 链、合约示例与前端工程串起来联调。

前置检查 ​

  • 已完成 第 05 章 · Solidity 基础。
  • 本机浏览器安装了 MetaMask（或其他注入 window.ethereum 的钱包）。
  • 已执行过 pnpm install，示例依赖安装完成。

本章前端位于 examples/06-dapp-vue，合约复用 examples/04-counter 的 Counter。这样你只需要理解一个合约，就能把注意力放在“前端如何与链交互”上。

1. dApp 的最小闭环 ​

四个角色各有边界：

  • 前端负责组装参数、展示状态，不碰私钥。
  • 钱包负责签名与授权，用户可以拒绝任何请求。
  • RPC 节点负责广播与查询，可能限流或不同步。
  • 合约负责真正的状态变更与事件。

3. 连接钱包 ​

连接分三步：检测注入对象、检查网络、请求账户。

vue
<script setup>
import { ref } from 'vue'
import {
  createPublicClient,
  createWalletClient,
  custom,
  http,
  parseAbi
} from 'viem'
import { hardhat, sepolia } from 'viem/chains'
import { formatCount, shortenAddress } from './lib/format.js'

const counterAddress = import.meta.env.VITE_COUNTER_ADDRESS
const rpcUrl = import.meta.env.VITE_RPC_URL
const counterAbi = parseAbi([
  'function number() view returns (uint256)',
  'function increment() returns (uint256)',
  'event NumberChanged(uint256 indexed oldValue, uint256 indexed newValue, address indexed operator)'
])

let publicClient = createPublicClient({
  chain: sepolia,
  transport: rpcUrl ? http(rpcUrl) : http()
})

const address = ref('')
const count = ref(null)
const status = ref('请先连接钱包')
const busy = ref(false)
let walletClient = null

// #region wallet-connect
async function connectWallet() {
  if (!window.ethereum) {
    status.value = '未检测到浏览器钱包，请先安装 MetaMask'
    return
  }

  const chainId = await window.ethereum.request({ method: 'eth_chainId' })
  const chain = [sepolia, hardhat].find(
    (item) => item.id === Number.parseInt(chainId, 16)
  )
  if (!chain) {
    status.value = '仅支持 Sepolia（11155111）或本地 Hardhat（31337）'
    return
  }

  const accounts = await window.ethereum.request({ method: 'eth_requestAccounts' })
  address.value = accounts[0]
  publicClient = createPublicClient({
    chain,
    transport: rpcUrl ? http(rpcUrl) : http()
  })
  walletClient = createWalletClient({
    chain,
    transport: custom(window.ethereum)
  })

  status.value = `已连接 ${shortenAddress(address.value)}`
  await refreshCounter()
  watchCounter()
}
// #endregion

// #region read-counter
async function refreshCounter() {
  if (!counterAddress) {
    status.value = '缺少 VITE_COUNTER_ADDRESS，请先部署合约并写入 .env'
    return
  }

  count.value = await publicClient.readContract({
    address: counterAddress,
    abi: counterAbi,
    functionName: 'number'
  })
}
// #endregion

// #region write-counter
async function increment() {
  if (!walletClient || !address.value) {
    status.value = '请先连接钱包'
    return
  }

  busy.value = true
  try {
    const hash = await walletClient.writeContract({
      address: counterAddress,
      abi: counterAbi,
      functionName: 'increment',
      account: address.value
    })
    status.value = `交易已广播：${shortenAddress(hash)}`

    const receipt = await publicClient.waitForTransactionReceipt({ hash })
    status.value = `已确认，区块 ${receipt.blockNumber}`
    await refreshCounter()
  } catch (error) {
    status.value = error.shortMessage ?? error.message
  } finally {
    busy.value = false
  }
}
// #endregion

// #region watch-events
let unwatch = null

function watchCounter() {
  unwatch?.()
  unwatch = publicClient.watchContractEvent({
    address: counterAddress,
    abi: counterAbi,
    eventName: 'NumberChanged',
    onLogs: () => refreshCounter()
  })
}
// #endregion
</script>

<template>
  <main>
    <h1>06 · 第一个 dApp</h1>
    <p>合约地址：{{ counterAddress || '未配置' }}</p>
    <p>当前计数：<strong>{{ formatCount(count) }}</strong></p>
    <p>状态：{{ status }}</p>

    <button v-if="!address" @click="connectWallet">连接钱包</button>
    <button v-else :disabled="busy" @click="increment">
      {{ busy ? '等待确认…' : 'increment' }}
    </button>
  </main>
</template>

几个关键点：

  • eth_requestAccounts 会弹出钱包授权窗口，必须由用户点击触发，不能在页面加载时自动调用。
  • window.ethereum 是钱包注入的 EIP-1193 提供者；不同钱包实现细节不同，但核心方法一致。
  • 连接后创建 walletClient，后续写交易都通过它发起。
  • 先校验链 ID，可以避免用户在错误网络上签名。

链 ID 用十六进制返回，需要用 Number.parseInt(chainId, 16) 转换。示例只接受两个网络：Sepolia（11155111）与本地 Hardhat（31337）。

publicClient.readContract 需要三样东西：

  1. address：合约地址。
  2. abi：至少包含被调用函数的片段。
  3. functionName：要调用的函数名。

返回值会按 ABI 自动解码，uint256 对应 JavaScript 的 bigint。展示时用 formatCount 转成字符串，避免大整数精度问题。

读和写用不同的 client

publicClient 负责读与监听，walletClient 负责签名与写。把两者分开，可以避免把“需要用户签名”的操作误做成静默调用。

注意几个容易忽略的细节：

  • writeContract 返回的是交易哈希，不是执行结果。
  • 交易可能成功上链但执行失败（status = 0），所以要用收据判断。
  • waitForTransactionReceipt 默认等待 1 个确认，测试网可能需要十几秒。
  • 用户拒绝签名时抛出的错误也应展示，而不是只写 console.log。

error.shortMessage 是 viem 对常见错误的人话版本；拿不到时再退回 error.message。

  'function number() view returns (uint256)',
  'function increment() returns (uint256)',
  'event NumberChanged(uint256 indexed oldValue, uint256 indexed newValue, address indexed operator)'
])

let publicClient = createPublicClient({
  chain: sepolia,
  transport: rpcUrl ? http(rpcUrl) : http()
})

const address = ref('')
const count = ref(null)
const status = ref('请先连接钱包')
const busy = ref(false)
let walletClient = null

// #region wallet-connect
async function connectWallet() {
  if (!window.ethereum) {
    status.value = '未检测到浏览器钱包，请先安装 MetaMask'
    return
  }

  const chainId = await window.ethereum.request({ method: 'eth_chainId' })
  const chain = [sepolia, hardhat].find(
    (item) => item.id === Number.parseInt(chainId, 16)
  )
  if (!chain) {
    status.value = '仅支持 Sepolia（11155111）或本地 Hardhat（31337）'
    return
  }

  const accounts = await window.ethereum.request({ method: 'eth_requestAccounts' })
  address.value = accounts[0]
  publicClient = createPublicClient({
    chain,
    transport: rpcUrl ? http(rpcUrl) : http()
  })
  walletClient = createWalletClient({
    chain,
    transport: custom(window.ethereum)
  })

  status.value = `已连接 ${shortenAddress(address.value)}`
  await refreshCounter()
  watchCounter()
}
// #endregion

// #region read-counter
async function refreshCounter() {
  if (!counterAddress) {
    status.value = '缺少 VITE_COUNTER_ADDRESS，请先部署合约并写入 .env'
    return
  }

  count.value = await publicClient.readContract({
    address: counterAddress,
    abi: counterAbi,
    functionName: 'number'
  })
}
// #endregion

// #region write-counter
async function increment() {
  if (!walletClient || !address.value) {
    status.value = '请先连接钱包'
    return
  }

  busy.value = true
  try {
    const hash = await walletClient.writeContract({
      address: counterAddress,
      abi: counterAbi,
      functionName: 'increment',
      account: address.value
    })
    status.value = `交易已广播：${shortenAddress(hash)}`

    const receipt = await publicClient.waitForTransactionReceipt({ hash })
    status.value = `已确认，区块 ${receipt.blockNumber}`
    await refreshCounter()
  } catch (error) {
    status.value = error.shortMessage ?? error.message
  } finally {
    busy.value = false
  }
}
// #endregion

// #region watch-events
let unwatch = null

function watchCounter() {
  unwatch?.()
  unwatch = publicClient.watchContractEvent({
    address: counterAddress,
    abi: counterAbi,
    eventName: 'NumberChanged',
    onLogs: () => refreshCounter()
  })
}
// #endregion
</script>

<template>
  <main>
    <h1>06 · 第一个 dApp</h1>
    <p>合约地址：{{ counterAddress || '未配置' }}</p>
    <p>当前计数：<strong>{{ formatCount(count) }}</strong></p>
    <p>状态：{{ status }}</p>

    <button v-if="!address" @click="connectWallet">连接钱包</button>
    <button v-else :disabled="busy" @click="increment">
      {{ busy ? '等待确认…' : 'increment' }}
    </button>
  </main>
</template>

8. 错误处理与用户提示 ​

场景前端表现建议处理
未安装钱包window.ethereum 为 undefined提示安装，不阻塞页面其他内容
网络不对链 ID 不是 Sepolia 或本地 31337提示切换，或调用 wallet_switchEthereumChain
用户拒绝签名抛出 UserRejectedRequestError提示“已取消”，不要重复弹窗
余额不足估算 Gas 失败提示领取测试币
合约地址错误readContract 返回空或报错校验地址来自最近一次部署
交易执行失败收据 status = 'reverted'解码 revert 原因并展示

原则是：钱包负责签名，前端负责解释。用户看到的应该是“发生了什么、下一步做什么”，而不是原始 JSON 错误。

9. 常见坑 ​

  • 在 onMounted 里自动请求账户：多数钱包会拦截，必须在用户手势内调用。
  • 把交易哈希当成成功：哈希只代表已广播，最终结果要看收据。
  • 读合约用了 walletClient：读操作不需要签名，反而可能触发不必要的授权。
  • 把 uint256 直接转 Number：超过 2^53 会丢精度，始终用 bigint。
  • ABI 只写函数名不写参数：parseAbi 会校验签名，写错会在调用时失败。
  • 前端保存私钥：私钥永远不应进入浏览器代码或仓库。
