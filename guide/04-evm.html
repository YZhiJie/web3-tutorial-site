04 · 以太坊与 EVM ​

零基础约 5 学时 前置：/guide/03-transactions-gas验证于 2026-11-04

本章目标 ​

完成这一章后，你应该能够：

  • 说清外部账户（EOA）与合约账户的区别。
  • 理解 EVM 的栈、内存、存储与 calldata 各自保存什么。
  • 看懂一笔合约调用从交易进入 EVM 到状态写入/回滚的过程。
  • 用 viem、ethers 或 cast 读取合约状态。

前置检查 ​

  • 已完成 第 03 章 · 交易生命周期与 Gas。
  • 知道什么是 nonce、gas limit 与交易收据。

1. EVM 在以太坊中的位置 ​

以太坊可以粗略分成四层：

层作用本章关注点
网络层P2P 传播交易与区块交易如何进入节点
共识层决定哪个区块有效最终性与确认
执行层（EVM）执行交易、修改状态本章重点
应用层合约与 dApp通过 ABI 调用

EVM 是一个确定性的状态机：给定相同的初始状态和同一笔交易，所有节点必须得到相同的结果。这也是智能合约“可验证”的基础。

2. 账户与状态 ​

以太坊有两种账户：

  • 外部账户（EOA）：由私钥控制，可以发起交易。
  • 合约账户：由代码控制，没有私钥，只能被交易或其他合约调用。

每个账户都有：

  • nonce：该账户已发送的交易数量（EOA）或创建的合约数量（合约账户）。
  • balance：以 wei 计的 ETH 余额。
  • code：合约字节码（EOA 为空）。
  • storage：合约的持久化键值存储（EOA 为空）。

状态是全局的

“世界状态”可以理解为所有账户的集合。交易执行成功后，状态树会被更新；执行失败则本次交易中的所有状态修改回滚，但已消耗的 Gas 不会退还。

3. EVM 执行模型 ​

EVM 执行字节码时，主要使用四块区域：

区域生命周期访问成本典型用途
栈（Stack）单次调用很低算术、比较、跳转
内存（Memory）单次调用中等，按需扩展临时数据、ABI 编码
存储（Storage）永久很高合约状态、映射、所有权
Calldata单次调用低函数参数与外部输入

EVM 是栈式虚拟机：大多数指令从栈顶取操作数，再把结果压回栈顶。Solidity 编译器负责把高级语言转换成这些 opcode。

为什么存储最贵？

存储写入会改变世界状态，需要被所有全节点持久化。读取也有冷/热访问差异。因此合约设计里常见的优化是：能在内存里算完的，不要写存储；能批量更新的，不要逐条写。

5. 示例合约的核心逻辑 ​

下面是 examples/04-counter 中的增量逻辑（省略了权限与重置函数）：

solidity
function increment() external returns (uint256) {
    uint256 oldValue = _number;
    _number = oldValue + 1;
    emit NumberChanged(oldValue, _number, msg.sender);
    return _number;
}

这段代码做了三件事：

  2. 将新值写回存储。
  3. 触发 NumberChanged 事件，供链下索引。

注意 _number 是 private，但“private”只限制其他合约直接访问，不意味着链上数据不可见。任何人都可以从存储或事件中读取它。

失败也要付费

交易失败时，合约状态回滚，但验证者已经执行了字节码，因此已消耗的 Gas 不会退还。估算 Gas 时不要把 gasLimit 当作实际扣费上限。

8. 常见误解 ​

  • “合约账户也有私钥”：没有。合约由代码控制，调用必须通过 EOA 或其他合约。
  • “private 变量链下看不到”：链上数据公开可读，private 只是 Solidity 的可见性修饰。
  • “view 函数完全不花钱”：不花链上 Gas，但 RPC 提供商可能有速率限制。
  • “存储写入永远 20000 Gas”：实际成本取决于冷/热访问、是否首次写入以及退款规则。

9. 练习题 ​

  1. 在本地链部署 Counter，连续调用两次 increment()，用收据对比两次的 gasUsed 是否相同。
  2. 修改 Counter.sol，让 setNumber 同时校验新值不超过 100，并补一条测试。
  3. 用 cast logs 或区块浏览器找出 NumberChanged 事件，说明三个 indexed 参数分别是什么。
  4. 用 viem 的 getContractEvents 读取最近 5 条事件，并按 newValue 排序。
